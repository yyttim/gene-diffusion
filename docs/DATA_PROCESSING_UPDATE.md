# GeneDiffusion 数据处理更新

## 重要更新：全基因组数据利用

根据用户需求，我们已更新数据处理策略以训练一个**生物通用大模型**。

### 主要变更

#### 1. 序列片段长度
- **从5kb → 10kb**：每个训练样本现在是10,000 bp的序列片段
- 对应约1,666个6-mer tokens（10kb序列）

#### 2. 数据覆盖策略
- **之前**：只提取注释区域（基因、外显子等）附近的序列
- **现在**：使用滑动窗口扫描**整个基因组**，包括所有区域：
  - 编码区域（基因、外显子、CDS）
  - 非编码区域（内含子、基因间区）
  - 调控区域（启动子、增强子等）
  - 重复序列区域

#### 3. 数据量
- **目标**：3M（300万）个训练样本
- **实际可生成**：约297M（2.97亿）个样本（使用80%重叠率）
- **基因组数据总量**：597 GB
- **物种数量**：230个哺乳动物物种

### 数据处理参数

```python
# GenomicDataset 默认参数
seq_length = 10000          # 10kb片段
overlap = 0.8               # 80%重叠率
stride = 2000               # 2kb步长
max_sequences_per_species = 100000  # 每个物种最多10万个片段
```

### 生物学意义

1. **全基因组学习**：模型将学习整个基因组的序列模式，不仅限于已知功能区域
2. **发现未知模式**：可能发现目前未注释的功能元件
3. **更好的上下文理解**：10kb窗口能捕获长程调控关系
4. **通用性**：适合作为生物序列的基础模型

### 训练数据示例

每个训练样本包含：
- `input_ids`: 10kb序列的6-mer token表示（约1,666个tokens）
- `annotations`: 对应的功能注释（如果有）
- `species_id`: 物种标识（0-229）
- `annotation_coverage`: 注释覆盖率（0-1）

### 使用建议

1. **批次大小**：建议使用较小的batch size（如16或32），因为序列更长
2. **内存需求**：每个样本约需要13KB内存（1666 tokens × 2 bytes × 4 tensors）
3. **训练时间**：297M样本，1个epoch约需要930万步（batch_size=32）

### 注意事项

1. **存储需求**：完整数据集需要约3TB存储空间（297M × 10KB）
2. **IO性能**：建议使用SSD存储和多进程数据加载
3. **内存使用**：可以使用`cache_sequences=False`来减少内存占用
4. **训练策略**：考虑使用curriculum learning，从短序列逐渐过渡到长序列

### 未来优化

1. **动态长度**：支持可变长度序列（5kb-50kb）
2. **染色体级别处理**：直接处理整条染色体
3. **多物种对齐**：利用同源序列信息
4. **在线数据增强**：反向互补、随机mask等
